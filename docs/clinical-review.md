# 临床审定清单（待医院逐条确认）

词表 `web/engine/catalog.json` 里的「术前准备 / 术后注意 / 住院注意」条目，会**原文照录**进每本书的封底（家长陪护说明）。这些条目由本项目编写，**未经临床审核**，上线前必须由医院逐条过。

这份清单只做一件事：把「需要临床判断、不该由工程侧私下决定」的条目单独挑出来，供审定时逐条打勾。改条目只改 `catalog.json`，不需要动代码。

对应词表版本：`catalog.json` → `version: 0.2.0-demo`（`review: demo`）。

---

## 一、已被个体事实门控的条目（机制说明）

这类条目**不是**术式常识，而是取决于这个孩子实际怎么做。词表里写成带 `requires` 的对象，事实没确认就整条不出（`web/engine/compose.mjs` 组装 `cautions` 时过滤）；确认了才出现，和故事页同口径。

| 术式 | 条目原文 | 出现条件 |
|---|---|---|
| 扁桃体切除术 / 腺样体切除术 | 手背留置针建立静脉通路 | `device = iv`（家长确认「会留一只」） |
| 腹腔镜阑尾切除术 / 开腹阑尾切除术 / 腹腔镜腹股沟疝修补术 | 留置针穿刺 | `device = iv` |

> 为什么未确认时是"整条不出"而不是写成"如果"：这是一份 to-do 清单，清单上出现「留置针穿刺」就等于告诉家长"你的孩子要扎留置针"。

**需要医院确认的是措辞本身**（不是出现条件）：
- [ ] 「手背留置针建立静脉通路」——手背是否为贵院常规穿刺部位？若常用前臂/头皮，请改成不指定部位的说法。
- [ ] 「留置针穿刺」——是否统一用「静脉留置针穿刺」这类规范表述。

## 三、审定后怎么改（只改数据，不改代码）

| 审定结论 | 改法 |
|---|---|
| 保留 | 不动 |
| 删除 | 从该术式的 `cautions` 数组里删掉这一条 |
| 改成标准表述 | 直接替换字符串内容（必须是院内原文，不要"合理改写"） |
| 只在某个条件下才适用 | 把该条改成 `{ "text": "…", "requires": [{ "fact": "…", "has_id": "…" }] }`，事实未确认时自动不出现 |

改完跑 `node tooling/check-unconfirmed.mjs`：它会断言「未确认的字段不得以肯定句或既成配图出现」，并检查注意事项分组没有被清空。另外 `node tooling/make-cases.mjs` 会把 `data/raw/*.txt` 重烘一遍并逐本过事实保真校验。

## 四、当前已知的未覆盖项（供审定参考）

- **没有**任何一条涉及：导尿/插尿管、备血/输血、预防性抗生素、具体禁食小时数 —— 这些一律不写进词表，等医院给出成文规范后再加。
- 术式覆盖只到 8 个（ENT 2、小儿外科 3、儿内科 2、骨科 1），其余术式走「清单书」或不支持。
- 「术前准备」以外的口头宣教（如术后饮食进阶、复诊时间）目前完全不覆盖，不要指望这本书替代出院宣教。
